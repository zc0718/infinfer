- **测量陷阱 2：断点也会改变结论**（2026-11-26 实测）。在 `kat_k0_run` 上插 `Z0` 断点再移除后继续，an505 的 k0 会**跑到底并报退出码 13**（三次一致）；同一镜像只 `c` 不停则停在 `T05`，完全不接 gdb 则 lockup。原因是 QEMU 越过断点/监视点必然单步，而单步在本机会破坏指令流 ⇒ **`W0d` 是假象，不能当成“其实是通的”**。
- **测量陷阱 3：写监视点要选“只会被写一次”的地址**。`Z2` 在 `7fffec`（`kat_check` 的 saved LR）上能正常触发，但该槽先被 `kat_startup_init` 的 `push {r4,r5}` 与 `kat_check` 的 `push {lr}` 合法写过，而越过一次监视点又必须单步 ⇒ 这条路在本案走不通，改用阶段二分。
- 无 gdb 客户端时的最小替代：`arm-none-eabi-gdb` 缺 `libncursesw.so.5`（本机只有 .so.6），改用 QEMU gdbstub 的 RSP 直接对话（`/tmp/rsp.py` 是当时写的 100 行版本，支持 `read/regs/step/cont/bp/frame`）。
- **测量陷阱 4：板型 RAM 区间要用 `info mtree` 读，不要凭型号猜**（2026-11-26 实测）。`qemu-system-arm -M mps2-an505 -monitor stdio -S` 然后 `info mtree -f`，FlatView `cpu-secure-memory-0` 里才看得出数据 RAM 是 `mps.ram @ 0x80000000..0x80FFFFFF`，而 `0x00400000..0x007FFFFF` 是 `tz-mpc-upstream`（MPC 包装，非通用 RAM）。栈放到映射之外时 **push 被静默丢弃、pop 返回垃圾**，症状是"返回地址变成 0/数据地址、PC 跳飞、走零区、最后 UNDEFINSTR"——看起来像算子/编译器缺陷，而且栈浅的链（k0/k1）**照样通过**，极容易被判成"这条链的代码有问题"。
